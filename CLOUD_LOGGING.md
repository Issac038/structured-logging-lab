# Cloud Logging Integration Guide

This document explains how the structured JSON logs produced by the Orders API integrate with cloud logging services.

## Overview

The JSON logs generated by pino can be directly ingested by modern cloud logging platforms. Each JSON object automatically becomes a structured log entry with searchable, queryable fields.

## How It Works

### Log Entry Structure
Each log line is valid JSON:
```json
{
  "level": 30,
  "time": 1787803025293,
  "pid": 17,
  "hostname": "orders-api-container",
  "reqId": "7ed81bce-a767-4af7-9dc5-5653c63855d3",
  "method": "GET",
  "path": "/",
  "msg": "root.endpoint.accessed",
  "service": "orders-api"
}
```

Cloud logging services parse this JSON and create indexed fields for each key:
- `level` → filterable by severity
- `time` → indexed for time-range searches
- `reqId` → searchable for request tracing
- `service` → filterable by service name
- `method`, `path` → queryable for API analysis
- `msg` → searchable event type

## Popular Cloud Logging Services

### Google Cloud Logging (Cloud Logging/Stackdriver)

**Integration:**
- Applications write JSON to stdout
- Cloud Logging agent or Kubernetes captures logs
- JSON fields automatically become queryable Log Entry fields

**Example Query (Cloud Logging syntax):**
```
resource.type="k8s_container"
jsonPayload.level=50
jsonPayload.service="orders-api"
```

**Benefits:**
- Automatic JSON parsing
- Field extraction without configuration
- Logs searchable immediately
- Integration with Cloud Trace for distributed tracing
- Custom metrics from log fields
- Alerting based on field values

### Amazon CloudWatch Insights

**Integration:**
- Application logs JSON to CloudWatch Logs
- CloudWatch Insights parses JSON automatically
- Fields become queryable

**Example Query (CloudWatch Logs Insights):**
```
fields @timestamp, @message.reqId, @message.msg
| filter @message.level = 50
| stats count() by @message.service
```

**Benefits:**
- Real-time log ingestion
- Full-text and field search
- Metrics derived from logs
- Integration with CloudWatch Alarms
- Log pattern analysis

### Grafana Loki

**Integration:**
- Applications ship JSON logs (e.g., via Promtail)
- Loki indexes labels extracted from logs
- Fields become queryable labels or parsed content

**Example Query (LogQL):**
```
{job="orders-api"} | json level="level" | level >= 50
```

**Configuration (Promtail):**
```yaml
scrape_configs:
  - job_name: docker
    docker: {}
    relabel_configs:
      - source_labels: ['__meta_docker_container_name']
        target_label: 'container'
    pipeline_stages:
      - json:
          expressions:
            level: level
            reqId: reqId
            service: service
```

**Benefits:**
- Log aggregation from multiple sources
- Cost-effective (no need to index all fields)
- Integration with Grafana dashboards
- Label-based searches
- Pattern detection and alerting

### ELK Stack (Elasticsearch, Logstash, Kibana)

**Integration:**
- Application sends JSON to Logstash
- Logstash enriches and forwards to Elasticsearch
- Elasticsearch indexes each field
- Kibana visualizes and queries

**Logstash Configuration:**
```logstash
input {
  tcp {
    port => 5000
    codec => json
  }
}

filter {
  if [level] == 50 {
    mutate { add_tag => [ "error" ] }
  }
}

output {
  elasticsearch {
    hosts => ["elasticsearch:9200"]
    index => "orders-api-%{+YYYY.MM.dd}"
  }
}
```

**Benefits:**
- Powerful field transformations
- Rich visualization in Kibana
- Machine learning for anomaly detection
- Advanced aggregations
- Full-text and structured search

### Datadog

**Integration:**
- Application writes JSON to stdout
- Datadog agent collects logs
- JSON parsed automatically
- Fields indexed for search

**Example Query:**
```
service:orders-api level:error @reqId:*
```

**Benefits:**
- Out-of-the-box integration
- Live log tailing
- Automatic trace correlation
- Faceted search on any field
- Log-based metrics
- Dynamic sampling

## Field Mapping Examples

### Standard Fields → Cloud Logging
| JSON Field | Google Cloud Logging | CloudWatch Insights | Datadog |
|-----------|-------------------|-------------------|---------|
| `level` | `severity` | `@message.level` | `level` |
| `time` | `timestamp` | `@timestamp` | `timestamp` |
| `reqId` | `labels.reqId` | `@message.reqId` | `request_id` |
| `service` | `resource.labels.service_name` | `@message.service` | `service` |
| `msg` | `jsonPayload.msg` | `@message.msg` | `message` |
| `error` | `jsonPayload.error` | `@message.error` | `error` |

## Advanced Use Cases with Structured Logs

### 1. Distributed Request Tracing
```
Propagate reqId across services:
  Request enters Service A
  → Service A logs with reqId=ABC123
  → Service A calls Service B, passes reqId in header
  → Service B logs with reqId=ABC123
  → Service B calls Service C, passes reqId in header
  → Service C logs with reqId=ABC123
  
Query all services: filter by reqId=ABC123
```

### 2. Real-Time Dashboards
**Example Grafana Dashboard Panel:**
- "Errors per second": count logs where `level==50` per minute
- "Top error types": group by `msg` field, count occurrences
- "Latency by endpoint": measure time between log entries for same `reqId`
- "Request distribution": facet by `path` and `method`

### 3. Alerting Rules
**Alert on error rate spike:**
```
SELECT COUNT(*) FROM logs 
WHERE service='orders-api' AND level=50
GROUP BY service
HAVING COUNT(*) > 10 IN LAST 5min
```

**Alert on missing database connection:**
```
ALERT missing_db_connection 
IF count_over_time({service="orders-api",msg="db.connection.failed"}[5m]) > 3
```

### 4. Cost Optimization
With structured logs, cloud providers can:
- Index only critical fields (e.g., `level`, `reqId`, `service`)
- Exclude verbose fields from indexing (e.g., raw `msg` text)
- Sample high-volume endpoints (e.g., health checks)
- Compress historical data

Example (Google Cloud Logging exclusion):
```
resource.type="k8s_container"
jsonPayload.path=="/health"
```

## Implementation Checklist

### For Kubernetes/Container Deployment
- ✅ Application logs JSON to stdout (already done with pino)
- ☐ Configure log collector (Fluentd, Logstash, etc.)
- ☐ Set log aggregation service (Loki, Datadog, etc.)
- ☐ Configure field extraction/parsing
- ☐ Set up dashboards for key metrics
- ☐ Create alerting rules for errors
- ☐ Test log retention policies

### For Serverless (AWS Lambda, Google Cloud Functions)
- ✅ Application logs JSON to stdout (already done)
- ☐ Enable log streaming to CloudWatch/Cloud Logging
- ☐ Configure CloudWatch Insights or Cloud Logging queries
- ☐ Set up alarms on parsed fields
- ☐ Create custom metrics from log values

### For Log Aggregation
- ✅ JSON logs are production-ready
- ☐ Add trace ID propagation for distributed tracing
- ☐ Include deployment metadata (version, environment)
- ☐ Add custom business metrics to relevant logs
- ☐ Document log schema for team

## Example: Google Cloud Logging Dashboard Query

```sql
-- Find all errors with their request context
SELECT
  timestamp,
  jsonPayload.reqId,
  jsonPayload.msg,
  jsonPayload.error,
  jsonPayload.service,
  labels.pod_name
FROM `project.dataset.appengine_app`
WHERE
  timestamp >= TIMESTAMP.sub(CURRENT_TIMESTAMP(), INTERVAL 1 HOUR)
  AND jsonPayload.level >= 50
ORDER BY
  timestamp DESC
LIMIT 100
```

## Summary

**Structured JSON logging enables:**
1. **Immediate indexing** - No parsing needed, fields are ready to search
2. **Multi-dimensional queries** - Find logs by any combination of fields
3. **Correlation** - Follow single requests across multiple services
4. **Metrics derivation** - Convert logs to metrics for dashboards
5. **Cost-efficient storage** - Index selectively, compress well
6. **Tool integration** - Works with every major cloud platform
7. **Team efficiency** - Faster debugging, fewer incidents

The Orders API's pino-based logging is fully compatible with modern observability stacks and requires zero changes to integrate with your cloud platform of choice.
